## 1. 의도

원하는 느낌이나 상황에 맞는 곡을 **나중에 한 번에 다시 듣기** 위한 개인용 웹앱.
태그별 플레이리스트를 매번 만드는 건 번거롭고, 태그 조합은 플레이리스트로 사실상 불가능하다.
그래서 곡에 태그를 달고 태그를 겹쳐 골라 곡을 꺼낸다.

태그의 쓰임 4가지 (한 곡에 겹쳐 붙을 수 있음):

| # | 종류 | 예시 |
|---|---|---|
| 1 | 계절·시간대 | #가을 #새벽 |
| 2 | 그 시절의 나 | #20대초반여름 #대학원생때 #첫취준때 |
| 3 | 조합 | #여름 + #재즈 / #힙합 / #EDM |
| 4 | 상황 | #노래방 #작업 #친구초대 |

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 곡 검색 → 선택 → 태그 달기를 거의 한 번에 끝낸다.
- 태그를 겹쳐 골라 곡 목록을 좁힌다.
- 로컬에서 `npm run dev`로 띄워 실제로 쓸 수 있다.

**비목표 (첫 버전에서 안 함)**
- 로그인, 여러 기기 동기화, 공유, 서버(Spring 포함)
- 모바일 화면
- 데이터 백업 (JSON 내보내기/가져오기). 나중에 넣는다
- 배포 (나중에 홈서버 예정, 지금은 비워둠)
- 실제 음악 재생, 외부 서비스로 플레이리스트 내보내기
- 수익화

**실패 조건**
- 태그 다는 게 플레이리스트 만드는 것만큼 귀찮으면 실패. **입력 속도가 최우선.**

## 3. 제약

- 사용자 1명, 기기 1대, 브라우저 저장만. **기기는 PC 브라우저.** 마우스와 키보드 기준으로 만들고, 문서의 "탭"은 클릭으로 읽는다.
- PC에서도 한글 입력은 조합 중에 엔터가 눌릴 수 있다. 태그 입력창은 조합 중(`isComposing`)인 엔터를 무시해야 한다.
- 곡 정보는 iTunes Search API. 인증 없음, CORS 허용(`access-control-allow-origin: *` 확인함), **분당 약 20회 제한**.
- `country=KR`은 곡(`entity=song`) 검색 결과가 0건이다. **`country=US` 고정.** US에서도 한글 검색어는 동작한다 (2026-10-21 테스트, 15곡 중 14곡은 아티스트+제목 검색 1위가 원곡).
- iTunes 결과의 곡명은 대부분 영문 ("밤편지" → "Through the Night"). 한글 그대로인 곡도 있다.
- 일부 곡명에 보이지 않는 문자 `U+200E`가 섞여 있다. 저장 전에 제거.
- 앨범아트·미리듣기는 Apple 약관상 홍보 목적 사용이 원칙. 개인 로컬용 첫 버전에서는 앨범아트 표시만 하고, 미리듣기는 쓰지 않는다. 공개 배포 전에 다시 검토.

## 4. 결정된 사항

### 기술
- TypeScript + React + Vite
- 저장: IndexedDB (Dexie)
- 바뀔 수 있는 부분 3개는 인터페이스 뒤에 둔다.

| 인터페이스 | 첫 구현 | 나중 후보 |
|---|---|---|
| `SongSearch` | iTunes Search API | Spotify 등 |
| `SongRepository` (곡·태그·그룹 저장) | IndexedDB | Spring 서버 API |
| `Player` (곡 재생 연결) | 유튜브 검색 링크를 새 탭으로 | 듣는 곳 정해지면 결정 |

### 화면 1: 곡 추가 → 태그 달기
흐름: `검색창에 곡명 입력 → 곡 선택 → 칩 탭 / 태그 입력 후 엔터 → 끝`

- **검색 결과는 두 구역**: 위에 "내 곡"(이미 저장한 곡), 아래에 "iTunes 결과".
  - 내 곡을 고르면 검색을 건너뛰고 바로 태그 단계로 간다.
  - iTunes 결과에서 제목에 Instrumental / Karaoke / Piano 같은 버전 표시가 있으면 아래로 내린다 (빼지는 않음).
  - 이미 저장한 곡은 iTunes 구역에 중복으로 보이지 않는다.
- **곡 선택 후**:
  - 표시 제목을 고칠 수 있다 (예: "Through the Night" → "밤편지"). 원래 제목도 남긴다.
  - 달린 태그는 칩으로 보이고, ✕로 뗀다.
  - 최근 쓴 태그를 칩으로 보여주고, 탭 한 번으로 단다.
- **태그 입력창 하나로 조회 + 생성**:
  - 입력하면 기존 태그가 곡 수와 함께 자동완성된다.
  - 목록에 없는 단어에서 엔터 → 새 태그를 만들고 바로 단다.
  - 키보드만으로 끝낼 수 있어야 한다 (↑↓, 엔터).

### 화면 2: 태그로 꺼내기
- 태그를 그룹별로 보여주고, 태그마다 곡 수를 표시한다.
- 태그를 탭해서 여러 개 고르면 곡 목록이 좁혀진다.
- **필터 규칙: 같은 그룹 안은 OR, 다른 그룹끼리는 AND.**
  - 예: #여름 + #가을 + #재즈 → (여름 또는 가을) 그리고 재즈
- 지금 선택 상태에서 골랐을 때 0곡이 되는 태그는 흐리게 표시한다. 같은 그룹 태그는 고르면 결과가 늘어나니까 흐리게 하지 않는다.
- 결과의 각 곡에 ▶ 버튼 → `Player`로 연결한다. "전체 재생" 자리는 만들어두되 첫 버전에서는 비활성으로 둔다.

### 화면 3: 태그·그룹 관리
사용자 요구: 태그는 "등록, 취소, 커스텀이 간단"해야 한다. 아이디어 노트 MVP에도 "태그 생성·수정·삭제, 그룹 지정"이 있다.

- 태그: 새로 만들기, 이름 바꾸기 (오타 수정), 지우기, 그룹 지정·해제.
- 태그를 지우면 그 태그가 달린 곡에서도 떨어진다.
- 그룹은 선택 기능이다. 사용자가 만들고, 이름 바꾸고, 지운다.
- 예시 그룹: 계절·시간대 / 그 시절의 나 / 장르·분위기 / 상황

## 5. 내 판단으로 정한 것 (승인됨)

- 태그 하나는 그룹 **최대 1개**에 속한다.
- 그룹 없는 태그는 각각 **혼자 하나의 그룹**으로 취급한다. 다른 태그와는 AND로 묶인다.
- 그룹을 지우면 그 안의 태그는 "그룹 없음"으로 옮긴다 (태그는 지우지 않는다).
- 태그 이름 앞의 `#`는 표시용이다. 저장할 때는 빼고, 앞뒤 공백을 지우고, 같은 이름은 하나로 합친다. 영문은 대소문자를 구분하지 않는다.
- 곡을 구분하는 기준은 iTunes `trackId`다. 싱글판과 앨범판처럼 trackId가 다르면 서로 다른 곡이다.
- "내 곡" 검색은 표시 제목, 원래 제목, 아티스트명에서 찾는다.
- iTunes 호출은 입력을 멈춘 뒤 잠깐 기다렸다가(디바운스) 보낸다. 분당 제한 때문이다.
- 곡을 지울 수 있고, 지우면 그 곡에 달린 태그 연결도 같이 지운다.
- 곡이 0개가 된 태그도 자동으로 지우지 않는다. 관리 화면에는 보이고, 꺼내기 화면에서는 숨긴다.
- 태그 이름을 이미 있는 이름으로 바꾸려 하면 거절한다 (합치기 기능은 첫 버전에서 뺀다).

## 7. 개발 방식

- 사용자 규칙: **테스트를 먼저 쓰고 실패를 확인한 다음 구현한다.** 순수 로직(필터 규칙, 태그 이름 정리, 검색 결과 정렬)은 단위 테스트로 검증한다.
- 완료 기준: 로컬에서 띄워서 아래 시나리오가 실제로 동작하는 것.
  1. "밤편지" 검색 → IU 원곡 선택 → 표시 제목을 "밤편지"로 수정 → #가을 새로 만들어 달기 → #새벽 새로 만들어 달기
  2. 다른 곡에 최근 태그 칩으로 #가을 달기
  3. 세 번째 곡에 #여름 + #재즈 달기
  4. 관리 화면에서 그룹 "계절·시간대"를 만들어 #가을, #여름 넣기
  5. 꺼내기 화면에서 #여름 + #가을 → 세 곡이 다 나옴. 여기에 #새벽 추가 → 밤편지만 남음
  6. 관리 화면에서 태그 이름 바꾸기 → 곡에 달린 태그도 바뀐 이름으로 보임
  7. 새로고침해도 데이터가 남아 있음
