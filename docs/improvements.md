# 이후 개선할 것

## 큰 작업

- **Spring 서버로 전환**: `SongRepository`를 서버 API 구현으로 바꾼다. 화면 코드는 그대로 둔다.
- **배포**: 홈서버에 올린다.
- **백업**: JSON으로 내보내고 가져온다. 지금은 브라우저 데이터를 지우면 다 사라진다.
- **로그인·여러 기기 동기화**: 서버 전환 이후에 한다.
- **모바일 화면**
- **듣는 곳 정하기**: 정해지면 `Player`를 새로 구현한다. 지금은 유튜브 검색 링크로 연다.
- **전체 재생**: 버튼 자리만 있고 비활성 상태다. 듣는 곳이 정해진 뒤에 한다.
- **플레이리스트 내보내기**: 외부 서비스로 보낸다.
- **곡 검색 출처 추가**: Spotify 등 다른 `SongSearch`를 붙인다.
- **태그 합치기**: 지금은 이미 있는 이름으로 바꾸려고 하면 거절된다.
- **공개 배포 전 Apple 약관 검토**: 앨범 아트 사용이 괜찮은지, 미리듣기를 넣을 수 있는지 확인한다.
- **곡 고유 코드(ISRC·ISWC) 저장**: 아래 참고.

### 곡 고유 코드 (ISRC·ISWC)

| 코드 | 무엇을 구분하나 | 예: 아이유 밤편지 |
|---|---|---|
| ISRC | 녹음 1개 (같은 곡이라도 리마스터·라이브는 다른 코드) | `KRA381700611` |
| ISWC | 작품(작곡) 1개 (리메이크·커버도 같은 코드) | `T-301.357.849-5` |

- **왜**: 지금 곡 구분 기준인 iTunes `trackId`는 Apple에서만 통한다. 같은 녹음이 싱글과 앨범에 실리면 trackId가 둘로 갈린다. ISRC가 있으면 이런 곡을 하나로 묶을 수 있고, Spotify 같은 다른 검색 출처나 재생처로 옮길 때 곡을 정확히 찾을 수 있다. ISWC가 있으면 리메이크곡과 원곡을 이어 볼 수 있다.
- **어디서 가져오나**: iTunes Search API 응답에는 두 코드가 없다(2026-10-22 확인).
  - MusicBrainz: 무료이고 인증이 필요 없다. 밤편지는 두 코드 모두 있었다. 요청은 초당 1회로 제한된다. 인디 곡은 등록돼 있지 않을 수 있다.
  - Spotify API (ISRC만 제공, 인증 필요)
  - Apple Music API (ISRC만 제공, 개발자 토큰 필요)
- **방식**: 두 코드 모두 값이 없을 수 있는 필드로 둔다. 곡을 저장할 때나 나중에 몰아서 채운다. 제목과 아티스트로 찾아 붙이면 엉뚱한 곡과 이어질 수 있으니, 후보가 여럿이면 사용자가 고르게 한다.
- **우선순위**: ISRC를 먼저 넣는다. ISWC는 리메이크를 이어 보는 기능을 만들 때 넣는다.

## 작은 작업

- 표시 제목 입력창은 한글 조합 판정을 `isComposing`으로만 한다. 태그 입력창처럼 `keyCode 229`도 확인하게 맞춘다.
- 삭제 버튼을 빠르게 더블클릭하면 확인 단계를 건너뛰고 지워진다.
- 태그 이름에 유니코드 정규화(NFC)와 보이지 않는 문자 제거가 없다.
- iTunes 검색이 실패한 뒤 "다시 시도" 버튼이 없다.
- 곡 저장이 실패해도(IndexedDB 오류) 화면에 아무것도 안 나온다.
- 원곡 제목에 "piano"가 들어 있으면 그 곡도 버전곡으로 보고 목록 아래로 내린다.
- 태그 이름을 공백만 다르게 바꾸면 입력창에 그 공백이 그대로 남아 보인다.
- 화면 스타일이 최소한이다.

## 써보고 다시 정할 것

- `#가을밤`이 있을 때 "가을"을 치고 엔터를 누르면 `#가을밤`이 달린다. 앞글자 일치를 빠른 선택으로 쳤기 때문이다. 새 태그로 만들려면 ↓로 고른다.
- 탭을 옮기면 꺼내기 화면에서 고른 태그 선택이 풀린다.
