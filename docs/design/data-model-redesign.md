# 사용자별 태그 관리와 공통 곡 데이터 설계

작성일: 2026-10-29
상태: 구현 완료. 코드와 함께 검토할 설계 문서.

## 1. 목표와 범위

곡은 모든 사용자가 참조하는 공통 데이터로 관리한다. 태그·그룹과 그 연결은 사용자별로 독립적으로 관리한다. 다대다 관계는 배열 대신 별도 매핑 테이블로 저장한다.

- IndexedDB와 Dexie를 유지한다.
- 화면은 기본 사용자 한 명으로 동작한다. 로그인·사용자 전환 UI는 제외한다.
- 공통 곡 제목 수정은 허용한다.
- 공통 곡 삭제와 백오피스 구현은 제외한다.
- 기존 데이터는 모두 삭제하고 새 구조로 시작한다. 데이터 이관은 구현하지 않는다.

기존 DB 삭제는 새 버전 앱이 실행되는 브라우저에서 수행한다. 새 DB의 데이터는 재접속해도 유지한다.

## 2. 데이터 모델

| 테이블 | 필드 | 주요 제약 |
|---|---|---|
| `users` | `id`, `name` | `id` 기본키 |
| `songs` | `trackId`, `title`, `originalTitle`, `artistName`, `albumName`, `artworkUrl`, `releaseDate`, `addedAt` | `trackId` 기본키. 모든 사용자에게 공통 |
| `tags` | `id`, `userId`, `name`, `nameKey`, `groupId`, `lastUsedAt` | `id` 기본키. `(userId, nameKey)` 유일 |
| `groups` | `id`, `userId`, `name` | `id` 기본키 |
| `songTags` | `userId`, `trackId`, `tagId` | `(userId, trackId, tagId)` 복합 기본키 |

- `nameKey`는 현재 태그 이름 정규화·대소문자 비교 규칙으로 생성한다.
- 태그는 최대 한 그룹에 속한다. `groupId`는 비어 있을 수 있으며, 지정한 그룹은 태그와 소유자가 같아야 한다.
- 곡–태그 연결의 사용자와 태그 소유자는 같아야 한다.
- 연결 대상 곡·태그·그룹의 존재 여부와 소유자는 저장소에서 검사한다. 위반한 쓰기는 거절한다.
- 같은 그룹 안은 OR, 다른 그룹끼리는 AND로 필터링한다. 그룹 없는 태그는 각각 독립된 그룹으로 취급한다.

예를 들어 사용자 A는 밤편지에 `#가을`을 붙이고 그 태그를 ‘계절’ 그룹에 둘 수 있다. 사용자 B는 다른 곡에 자신의 `#가을`을 붙이고 ‘분위기’ 그룹에 둘 수 있다. 어느 한쪽의 변경도 상대방의 태그·그룹·연결에 영향을 주지 않는다.

## 3. 저장소

저장소는 현재 사용자 ID를 기준으로 태그·그룹·곡–태그 연결을 조회하고 변경한다. 곡 정보는 사용자 구분 없이 공통으로 조회하고 수정한다.

- 곡 목록과 제목은 공통이다. 같은 곡을 다시 저장하면 기존 레코드를 반환한다.
- 태그·그룹 조회, 이름 중복 검사, 최근 사용 시각, 곡–태그 연결은 현재 사용자 기준으로 처리한다.
- 표시 제목 수정은 공통 `songs.title`에 반영하고, `originalTitle`은 유지한다.
- 태그 삭제는 해당 사용자의 연결과 태그를 함께 삭제한다.
- 그룹 삭제는 해당 사용자의 소속 태그를 그룹 없음으로 변경하고 그룹을 삭제한다.
- 사용자용 저장소의 곡 삭제 메서드를 제거한다.
- 곡에 연결된 현재 사용자의 태그를 매핑 테이블에서 조회해 화면에 표시한다.
- 기존 `music-tag` DB는 삭제하고, 새 구조는 `music-tag-v2` DB에 생성한다.
- 초기화 시 고정 ID `default`, 이름 `기본 사용자`인 사용자를 생성한다. 재실행해도 중복 생성하지 않는다.

## 4. 화면 동작

- 기본 사용자로 추가·꺼내기·관리 화면을 이용한다.
- 곡 검색·등록 시 공통 곡 목록을 사용한다.
- 표시 제목을 수정하면 모든 사용자에게 공통으로 반영한다.
- 곡 삭제 버튼을 제거한다. 자신이 붙인 태그를 떼는 기능은 유지한다.
- 태그·그룹 목록, 태그별 곡 수, 자동완성, 최근 사용 태그, 필터는 현재 사용자의 데이터만 사용한다.
- 다른 사용자의 태그 지정이나 그룹 변경은 현재 사용자의 화면에 영향을 주지 않는다.

## 5. 검증 기준

변경 대상의 테스트를 먼저 작성하고 실패를 확인한 뒤 구현한다.

- 두 사용자가 같은 이름의 태그와 그룹을 각각 생성할 수 있다.
- 같은 곡에 사용자별로 다른 태그를 붙일 수 있다.
- 같은 이름의 태그를 사용자별로 다른 그룹에 배치할 수 있다.
- 다른 사용자의 태그·그룹을 조회·변경하거나 연결에 사용하는 것은 허용하지 않는다.
- 태그·그룹 삭제와 최근 사용 시각 변경이 다른 사용자에게 영향을 주지 않는다.
- 제목 수정은 모든 사용자에게 반영되고, 곡 삭제 UI는 제공하지 않는다.
- 기존 DB가 삭제되고 새 DB는 기존 곡·태그·그룹 없이 시작한다.
- 새 DB의 곡 레코드에는 `tagIds` 배열이 저장되지 않는다.
- 신규 설치·재접속과 기존 필터·검색·태그 입력 동작을 검증한다.

완료 기준은 테스트·린트·타입 검사·빌드 통과와 기본 사용자 화면의 추가·꺼내기·관리 흐름 확인이다.
